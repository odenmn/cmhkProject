# 数据库增量迁移规则

本目录用于真实数据库升级，`../schema.sql` 仅用于全新安装，禁止将其作为真实库升级脚本执行。

## 执行规则

1. 先备份目标数据库，并保存相关表的 `SHOW CREATE TABLE` 结果。
2. 执行当前阶段的 `P*_PRECHECK.sql`，保存数量、空值、重复值和悬空关系结果。
3. 人工审核差异和冲突；存在异常时停止，不得为了通过迁移而覆盖或删除数据。
4. 按版本号顺序执行 `V001__*.sql`、`V002__*.sql` 等增量脚本，不得跳号或重复执行。
5. 执行当前阶段的 `P*_VERIFY.sql`，与升级前记录逐项核对。
6. 保存执行人、执行时间、脚本版本和验证结果。

当前项目暂不启用 Flyway 或 Liquibase，版本化 SQL 由人工确认后执行。若后续引入自动迁移工具，必须先为现有真实库建立经确认的基线版本，不能直接在应用启动时试跑历史脚本。

## 脚本要求

- 每个结构迁移必须包含或配套提供执行前检查、结构变更、数据回填、执行后核验和回滚/兼容说明。
- 不得删除或清空真实数据，除非已经统计影响范围并取得用户明确确认。
- 不得使用姓名、渠道名称等非唯一文本静默建立关系。
- 无法唯一匹配的数据必须进入异常清单。
- `mobile_plan_order.id_no` 是历史兼容字段，应用不得采集、写入或返回；历史数据是否清理必须单独确认。

P0只建立迁移基线，没有作用于真实库的结构变更。
